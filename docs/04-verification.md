# 04. Верификация

## 1. Подход

Проверка построена на самопроверяющихся Verilog-тестбенчах. Каждый тест:

1. автоматически подаёт `clk` и `reset`;
2. удерживает сброс несколько тактов;
3. загружает программу или подаёт воздействия;
4. ждёт завершения (`halt`) с таймаутом;
5. проверяет конкретные ячейки RAM, регистры или `matrix_rows`;
6. печатает `PASS`/`FAIL`;
7. пишет VCD-файл в `sim_build/`.

Ручное вмешательство не требуется.

## 2. Уровни проверки

| Уровень | Файл | Что проверяется |
|---|---|---|
| Модульный | `tb/tb_alu.v` | операции АЛУ, флаги `Z/C` |
| Модульный | `tb/tb_register_file.v` | запись/чтение, `R0`, сброс |
| Блочный | `tb/tb_memory.v` | RAM, Video, MMIO-декодер, пустые адреса |
| Интеграционный ISA | `tb/tb_soc.v` | команды, переходы, память, матрица |
| Прикладной | `tb/tb_task3.v` | программа №23 на двух массивах |

## 3. Запуск

```bash
make test
make lint
```

`make test` собирает и запускает все тестбенчи, складывает логи и VCD в `sim_build/`. `make lint` запускает `verilator --lint-only -Wall`.

### Ожидаемый результат

```text
PASS tb_alu: 10 checks
PASS tb_register_file: 4 checks
PASS tb_memory: 7 checks
PASS tb_soc: 22 checks, 262 cycles
PASS tb_task3: 20 checks, 203 cycles
```

`make lint` не должен выдавать предупреждений.

## 4. Что проверяет `tb_soc`

`tb_soc` загружает `programs/isa_smoke.hex` и проверяет:

- `ADD`, `SUB`, `AND`, `OR`, `XOR`, `NOT`;
- `ADDI`, `SUBI`, `ANDI`, `ORI`, `XORI`;
- `CMP`, `CMPI`;
- `LOAD`/`STORE` с `imm(rs1)`, включая косвенную адресацию;
- `JUMP`, `BEQ`, `BNE` с истинными и ложными условиями;
- `NOP`, `HALT`;
- запись/чтение видеопамяти и `matrix_rows`.

## 5. Программа №23

`tb_task3` проверяет удаление подряд идущих дубликатов:

| Параметр | Значение |
|---|---|
| Массив | `0x0000` |
| Длина | слово по адресу `0x00FF` |
| Режим | in-place, повторные вхождения заменяются нулями |
| Тест 1 | `1,1,2,2,2,5,5,7,8,9` → `1,0,2,0,0,5,0,7,8,9`, длина 10 |
| Тест 2 | `3,3,4,4,5` → `3,0,4,0,5`, длина 5 |

Тест проверяет все слова результата и слово длины. Фактический результат — `PASS tb_task3: 20 checks`.

## 6. Временные диаграммы

VCD-файлы создаются в `sim_build/`:

```text
sim_build/tb_alu.vcd
sim_build/tb_register_file.vcd
sim_build/tb_memory.vcd
sim_build/tb_soc.vcd
sim_build/tb_task3.vcd
```

Открыть в GTKWave:

```bash
gtkwave sim_build/tb_task3.vcd
```

Для анализа в GTKWave полезно смотреть:

- `clk`, `reset`, `halt`;
- `pc` / `instr_addr`;
- `ir`;
- `data_addr`, `data_we`, `data_wdata`, `data_rdata`;
- `flags` (`Z/C`);
- ключевые ячейки RAM.

Для наглядной проверки можно сохранить скриншоты: старт после сброса, цикл программы, запись нулей в дубликаты и переход в `HALT`.

`sim_build/` не хранится в git: диаграммы генерируются заново командой `make test`.

## 7. Границы проверки

Сейчас не проверяются:

- MMIO-устройства (их ещё нет в RTL);
- `COLLISION_CHK`;
- BCD и Pong;
- интерактивный мост;
- синтез, ресурсы и `Fmax`.

Эти пункты относятся к следующим этапам.
